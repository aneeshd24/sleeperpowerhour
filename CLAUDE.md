# CLAUDE.md — The Power Hour

Context for Claude Code working in this repo. Read README.md for the user-facing overview.

## What this is

A shareable website for Aneesh's 10-team Sleeper league, **jits and diddles** (league ID `1389360536516329472`, 2026 season, commissioner aneeshd24): power rankings with explanations, a live waiver/trade feed, weekly matchup odds, and "nerd lab" stats. It started as a copy of Dan's site for another league, with that league's people and one-offs removed. The league ID is `LEAGUE_ID` in `api/league.js` (the `SLEEPER_LEAGUE_ID` environment variable overrides it). Hosted on Vercel from GitHub; every push to the deployed branch deploys.

Set for this league: `EDITOR` is Aneesh (aneeshd24; his own flops lead the news and the footer credits him), `CHAMPION` is jp1648 (Help me i need a RB, 2025 title). Off until someone sets them up, all in `app.js`: `MONEY_WEEK`, `SHAKEUP` (with its fan poll, whose id must also be in `POLLS` in `api/poll.js`), `MESSAGE_VIDEO`, `CLIP`. `MEMBERS` in `lib/members.js` has every manager's first name and headshot (`assets/heads/`, cropped from the originals the owner dropped in `assets/headshots`; Aneesh's original is `dundi.jpeg`). An entry without `photo` keeps the Sleeper team picture wherever a headshot would go. The fan picks store (Upstash) is connected in Vercel. Headlines are written in a dramatic voice: each story type in `lib/stories.js` has a few takes, picked by date (`drama`). `demo/demo.json` is this league's snapshot from Oct 27, 2026 with that morning's PPR rankings.

League facts: full PPR (rankings and projections come from the sites' PPR lists: `SCORING` in `lib/sources.js`), 10 teams, starting slots QB, RB, RB, WR, WR, TE, FLEX, FLEX, K, DEF + 5 bench. Regular season ends week 14, playoffs start week 15, top 6 make it. Standings tiebreaker is points for.

## Architecture

No framework, no build step, no npm dependencies. Plain ES modules served as static files.

- `index.html`, `styles.css`, `app.js` — the site. The browser never calls the Sleeper API: it loads `/api/league?d=KEY` and `/api/ros?d=KEY`, where KEY is the Central date rolling over at 6am (`morningKey()`), so each is fetched once per morning and shared from the CDN (and kept an hour by the browser, `max-age=3600`: a key's snapshot never changes). Load order: the `<head>` preloads both Latin font files, `<link rel="modulepreload">`s `app.js` and every `lib/` module the page imports (add a new front-end module there too, or it becomes a second round trip), and an inline `<script type="module" async data-early>` imports only `lib/newsclock.js` and starts both data requests while the rest of the code downloads (`window.__early`, skipped in the demo); `loadLive()` reuses them through `early()` when the URL still matches and sets `window.__early` itself first if they never started, so a request is never made twice.
- `api/league.js` — the morning Sleeper snapshot: state, league, users, rosters, matchups weeks 1–14, transactions weeks 1–current, plus `fetched`. It only answers the current key from `leagueKey()` (any other `?d=` gets a 307 to it) and keeps each snapshot in the store (`once('league', key)`, 3 days), so a deploy (Vercel empties the CDN) never re-reads Sleeper. `X-Snapshot` says `store` or `live`. `max-age=3600, s-maxage=86400`; errors are `no-store`. Also exports `snapshot()` for scripts. Hash routing: `#live` (only during a live week), `#rankings`, `#wire`, `#matchups`, `#trades`, `#lab`.
- `api/ros.js` — Vercel serverless function (Node 18+, global `fetch`). Scrapes the three ROS sources, fetches Sleeper's `/players/nfl` (~5 MB), matches players to Sleeper IDs, returns `{ updated, sources, weights, players: {id: {n,p,t,i,a}}, values: {id: {v, r, spread, pos, wk, fl, cl, ir, sos, g, rk, prk, wkEst?}}, byes: {TEAM: week} }`. Bye weeks come from FantasyPros (`player_bye_week` on every ecrData row). Only the current `morningKey()` is served (others redirect). Sleeper's player map is slimmed to fantasy positions and stored on its own (`once('players', key)`), so it's read at most once per morning; the built body is stored for 3 days, or 1h when a ranking source failed (the retry re-scrapes the rankings and reuses the stored players). Edge-cached 24h (`s-maxage=86400`) and an hour in the browser (`max-age=3600`); if a source failed, 1h at the edge and not at all in the browser. No cron; the only database is the fan-picks store behind `api/votes.js`.
- `lib/newsclock.js` — the shared clock (page and API): `TZ`, `NEWS_CLOCK` (hold, late pull, night edition, game window), `morningKey`, `leagueKey`, `isOnHold`, `isNightDesk`, `inGameWindow`.
- `lib/snapstore.js` — `once(name, key, produce)`: each snapshot kept gzipped in the Upstash store (same env vars as the fan picks) under its clock key, with a lock so simultaneous first visitors share one pull. Without the env vars it falls back to pulling on each CDN miss.
- `lib/sources.js` — regex-only parsers (must run in Node without a DOM):
  - FantasyPros: `var ecrData = {...};` embedded in the page HTML (~400 players incl. K/DST).
  - DraftSharks: the page only server-renders 25 rows; the full list is `GET /ros-rankings/load-rows?offset=0&limit=600&...` (HTML `<tr class="player-row">` fragments, includes IDP, re-ranked within offense). Also provides weekly proj pts, floor, ceiling, injury risk %, SOS, projected games.
  - LeagueLogs: server-rendered `<table>`, 200 players incl. DST, no K (its plain `/rankings/ros` page is the PPR list). Its order nearly mirrors FantasyPros ECR, so it is weighted 0.5.
- `lib/consensus.js` — `normName` + `NICKNAMES` map, `buildIndex(sleeperPlayers)`, `matchRow`, `buildConsensus`. Rank → value is `100 * exp(-0.0115 * (rank-1))`, weighted average across sources (`SOURCE_WEIGHTS`). Missing weekly projections are filled by a per-position linear fit of DraftSharks pts vs value, falling back to `DEFAULT_FIT` if DraftSharks is down.
- `lib/engine.js` — `computeLeague(input)`: pure, no DOM, runs in browser and Node. Produces teams (sorted by power rank), weekly results, all-play, luck, efficiency, ROS best lineup (greedy fixed-then-flex), position-group ranks, power score + rank history, Monte Carlo playoff odds and championship odds (10k sims, seeded; the playoff bracket is simulated on Sleeper's fixed 4/6/8-team bracket, giving `champPct`/`finalPct`; `simulate` runs on team indexes and typed arrays but draws the same random numbers in the same order as the plain version it replaced, so its odds are reproducible), matchup previews, explanations (`explain`), tiers (`tierFor`), transaction feed with ROS value deltas (trades priced over replacement: each net extra player received costs `meta.replacement`, the mean value of the top 3 free agents, so consolidation trades are not penalised; waiver moves stay raw), best available free agents, "divisive" players.
- `lib/stories.js` — the newsroom, pure like the engine. `buildStories(D, {now, dateKey, editor, people})` scores candidate stories and returns `{lead, more}`: `STORY_COUNT` (5) slides, half last week and half this week. Recap side (`side()`): fresh trades and wire moves, unbeaten/winless/streaks (kicker "After week N"), last week's upsets/blowouts/nail-biters/explosions, `regret` (lost with the win on the bench, from `weeks[].optimal`), `robbed` (a top-30% score that lost), rank moves. Preview side (`PREVIEW`): game of the week, `danger` (an unbeaten or top-3 team projected to lose; it replaces that team's unbeaten recap), `mustwin` (biggest playoff-odds swing), `elim` (a loss leaves ≤5%), `shorthanded` (2+ ROS starters out or on a bye), and the live `dud`/`star`. `SEASON` (luck, sleeping giant) only fills in when both halves run dry. The top-scoring story leads; then at least two per half, one type each, a team leads at most one story per half and two previews never share a game; after the lead, recaps come before previews. `people` (roster id → first name) puts managers' names in some headlines. A date-seeded jitter rotates near-ties daily. `keyMatchup(D)` picks the game of the week by 0.55 × stakes + 0.45 × closeness, where stakes is the combined playoff-odds swing (`playoffIfWin − playoffIfLoss` from the simulation). `matchupQuips(D)` gives one data-driven one-liner per matchup, no repeated joke within a week.
- `api/votes.js` — fan picks. GET `?week=&voter=` returns `{week, open, counts: {"3-8": {"3": n}}, mine}`; POST `{week, pair, pick, voter}` records a vote (re-voting replaces the device's pick). Storage is Upstash Redis over its REST pipeline API with plain fetch (env `KV_REST_API_URL`/`KV_REST_API_TOKEN` or `UPSTASH_REDIS_REST_*`); without them GET returns `{enabled: false}` (200, no console noise), POST returns 503, and the UI hides voting. Server validates against the cached `/api/league` snapshot on its own host (current week, real pair, pick in pair), never Sleeper directly, and closes voting from Thursday 7:15pm Central through Monday or once the snapshot shows points. `VOTES_NOW` env overrides the clock in tests. Soft cap of 3 voters per hashed IP per matchup. Keys `ph:votes:{week}:{pair}` (hash voter→pick) and `ph:net:{week}:{pair}:{iphash}` (set), 120-day TTL. The client keeps its voter id in `localStorage` `ph-voter` and hides the split until you've voted.
- `lib/matchup.js` — `breakdown(D, preview)`: this week's lineups slot by slot (the starters set in Sleeper, from `preview.startersA/B`; best projected lineup when a team hasn't set one), position-group edges, and up to 6 prioritised "things to watch" (starters ruled out or on a bye, legal lineup swaps found by greedy slot-eligible bench swaps, doubtful/questionable starters, biggest edges, close or lopsided totals, the widest floor-ceiling swing player, QB stacks, shared NFL offenses, hot or cold form). The engine's `thisWeekProj` is zero for players ruled out or on a bye (`byes` input), which also feeds this week's win odds. `helpers.player(id)` returns name, NFL team, status, bye, proj, floor, ceiling.
- `lib/trades.js` — `tradeIdeas(D, rid)`: brute-force search of every 1-for-1, 2-for-1 and 1-for-2 swap with each other team (skill positions, value >= 8; about 25ms: per-player lookups are memoized, and the partner's lineup is only worked out once the requester's has cleared its bar). Kept only if the requester's best ROS lineup gains >= 0.3 pts/wk, the partner's doesn't drop and gains >= 0.1 unless they win the value side by >= 3, and value (over replacement, same rule as the trade ledger) is within max(6, 15% of the deal). Roster fallout is modelled: an extra player received forces the lowest-value skill player to be cut; a freed spot adds the best free agent. Max 2 ideas per partner and per incoming headliner. Explanations come from position-group ranks before and after. No AI model involved; it is a deterministic search.
- `lib/members.js` — `MEMBERS`: Sleeper user_id → `{first, photo?}` for the league managers, with headshots in `assets/heads/<photo>.jpg` (320px square JPEGs cropped from the originals, about 25 KB each). A picture that fails to load turns into its initials (`data-initials`) through one capturing `error` listener on the document (`initAvatarFallback`), so renders never attach their own. In `app.js`, `avatar(t)` stays the Sleeper team picture (the team photo uploaded in Sleeper's team settings, `t.teamPhoto` from `users[].metadata.avatar`, else the account avatar) (team pictures stay in the ranking rows, the wire and the matchup cards); `headshot(t, cls)` is the manager photo (falls back to `avatar`). Headshots appear in the headline photos (`leadFaces`, with a `STAMPS` label per story type), the manager card at the top of an opened ranking row (`managerCard`, plus `superlatives` badges), the game of the week poster (`faceoff`) and its playoff-drive legend, the busiest manager in the wire stat strip, who shook on each trade card (`dealFaces`), the partner on your best Trade Lab idea (`.pitch`), photo marks in the scatter chart and on your own line in the bump chart (`img`, `faceDot` in charts.js), your face next to the team picker (`paintMe`), and the editor line in the footer. Last place (the "This Guy Stinks" tier) gets the `.drained` grayscale. Keep them sprinkled: one or two personal moments per page, not every list. A new manager needs an entry in `MEMBERS` and a cropped photo.
- `lib/bullseye.js` — money week side pots. `bullseye(D, {week, target})`: during the week, every team's projection (banked plus the rest, same as the previews) sorted by distance from the target, plus `pWin` from 20k seeded draws of who lands closest; the week after, the final scores and the winner; `soon` before; null otherwise. `MONEY_WEEK` in `app.js` (week, target, prize, usual, title, honoree, flyer) drives a lead headline (`moneyStory`, always first while it runs), the bullseye board on the matchups page (`bullBoard`: rules, the $40 → $80 ticket, the flyer at `assets/money-week-flyer.jpg`, a target chart `bullTarget` on a square-root scale with the closest three as faces, and the full table) and a distance chip on each matchup card (`bullTag`). Set `MONEY_WEEK` to the next one, or null.
- Defending champion: `CHAMPION` in `app.js` (Sleeper user_id, season). `champTag`/`champBadge` put the `TROPHY` svg by their team name (ranking row, futures, headline rows, matchup cards, bullseye table), on their photo (headline, manager card, face-off, footer), and add a "Defending champion" badge to the manager card. Update it after each title.
- Matchup cards stay light: one moneyline row (`.ml`) under the win bar; `betLine` puts the rest of the book behind a "More odds" toggle (`.odds-open` on the card): spread, total, team totals, nail-biter (margin under 5) and blowout (20+) props from the same normal margin model as the win odds (`phi`), money week closest-to-target odds, and the playoff stakes line. The open selector is scoped (`.mu.open .mu-detail`) so the lineup breakdown and the odds open separately.
- The news clock: `NEWS_CLOCK` in `app.js`, in Central minutes from Sunday midnight (`weekMinute`). Sunday noon to 10:45pm (`onHold`) the headline card carries a yellow "Games in progress" strip (`.desk-note`). At 10:45pm (`late`) `leagueKey()` switches the league snapshot to `<morning key>-late`, a fresh CDN cache key, so the first visitor after Sunday night football triggers one new Sleeper pull (`/api/ros` keeps the morning key). From then until Tuesday 6am (`nightDesk`) the headlines are the night edition. `?at=<ISO time>` fakes the clock for testing. A single Sunday's late pull can be moved with `LATE_OVERRIDES` in `lib/newsclock.js` (that Sunday's Central date → minutes after midnight); the hold banner ends and the night edition starts at the moved time, and the late key covers the rest of the night, so there is no second pull.

Sleeper's own scoring isn't needed. The final-scores page stays reachable afterwards (`DATA.after`, rendered through `withData`). Test with a played-week demo and `?at=`.

### Power score

One formula for everyone: `WEIGHTS` in `lib/engine.js`, in priority order. Standing 40% (`standing` 0.31, place in the real standings: wins then points for; `winPct` 0.09), scoring 28% (`pfPerGame` 0.20, `allPlay` 0.04, `form` 0.04), schedule left 17% (`sos` 0.17), rest-of-season roster 15% (`rosProj` 0.13, `depth` 0.02). `PARTS` groups them; each team gets `t.parts` (standing, scoring, schedule, roster sub-scores) shown as the four bars on a ranking row, and `t.seed` (standings place). There is no admin page or published config: the page never passes weights, so every device computes the same ranks from the same snapshot (`computeLeague({ weights })` is only for scripts). Each metric is z-scored across the 12 teams; score = `50 + 22 * weighted z`, clamped 1–99. `sos` is schedule wins (`t.schedWins`): sum over the remaining regular-season games of P(win vs actual opponent) − P(win vs average opponent), using the same `projMean` and pooled SD as the playoff simulation, so the projection block runs before the power score. The engine also still returns `rosScore`, `sosScore`, `resultsScore`. Bye weeks (`byes` input from `/api/ros`) count everywhere: `weekProj(id, w)` is zero on a player's bye (and this week if ruled out); each team's `weekProj[w]` is its best lineup that week; `rosProj` is their regular-season average; `muWeek[w]` (week-specific strength) drives schedule wins and the simulation, so drawing a team in its bye-heavy week counts as easier. `effWeekly` (lineup display, position groups, Trade lab) is the per-game projection times health times the share of remaining regular-season weeks not lost to a bye. If `/api/ros` fails, ROS terms are dropped (schedule stays, using points per game) and the page shows a "results-only mode" notice. Rank history holds the ROS and schedule terms at today's value, so week-to-week movement comes from results only.

### Week in progress

After Thursday night the current week is partly played. An NFL team counts as played once any rostered player of theirs has a non-zero score in `matchups[upcoming]`. In `computeLeague`: `liveProj(id)` is actual points for played players, else `thisWeekProj`; each team gets `t.live = {banked, rest, left, played[]}` (locked starters' points, best lineup of not-yet-played players in the open slots, share of slots still open). `muWeek[upcoming]` becomes banked plus the blended rest, and `sdWeek[upcoming] = sd * sqrt(left)`, which drives the previews' win odds and the simulation (playoff and title odds). Previews carry `liveA/liveB`. `D.live = {week, teams}`. Season PF and records stay Sleeper's official numbers until the week is scored. The matchup breakdown tags played players FINAL and never suggests swapping them. `buildStories` adds a `dud` and a `star` story from the played games; the `editor` option (`EDITOR` in `app.js`, off by default) makes his own underperforming starter the dud and the lead. Hand-written headlines live in `PUNS` in `lib/stories.js`.

## Design system

Concept: a day game. A flat sky over a mowed football field; every surface is cartoon glass on a hard ledge: an inked outline, a bright sheen across the top, a hint of the field showing through. No blur, no soft shadows. Light only.

- Palette in `:root` of `styles.css`: `--grass #4CAF50`, `--grass-2 #8BC34A`, `--lime #CDDC39`, `--yellow #FFEB3B` (the first-down line: your team), `--amber #FFC107` (the goalposts: actions, the active tab, featured cards). Supporting: `--sky-1/2/3`, `--board #13301C` (scoreboards), `--turf #1B5E20` (end zone), white cards with `--tile`/`--tile-2` inner layers, `--ink`/`--ink-2`/`--ink-3` (all at least 4.5:1 on white and tile), `--good`/`--bad`/`--flag`, and matchup sides `--a`/`--a-ink` (blue, left team) vs `--b`/`--b-ink` (amber, right team).
- Text sitting directly on the grass must be `--ink` (5.2:1); the muted inks fail on green, so small text there goes on a white chip (`.sec-title`, `.day > h3`, filter pills).
- Type: Big Shoulders Display (numerals, team names, headings) + Albert Sans (body). Tabular numbers on. Both are self-hosted variable fonts in `assets/fonts` (Latin and Latin Extended WOFF2 from Google Fonts, SIL OFL, licence files alongside), declared at the top of `styles.css`; there is no Google Fonts request.
- `.glass` is the card, cartoon glass: an 88% white face (`--face`, so the grass tints it and a chalk yard line can show through faintly; every ink still clears 4.5:1 on it), a fixed 150px `--sheen` band over the top, and one shadow stack built from variables: `--rim` (inset highlight), your team's yellow ring (`--ring-w`, 0 unless it's yours), the ink outline (`--edge` 2.5px of `--outline`) around both, then the ledge (`--lift` of `--ledge-c`) as wide as the outline. States only change variables (`.mine .rank-card`, `.wire-team.mine`, `.mu.rim` and `.you-card` set `--ring-w: 4px`), so set colours with `background-color`, never the `background` shorthand, or the sheen disappears. `.glass.rim` = featured, on a gold ledge (top-3 ranks, trades, best trade idea, scoreboards). The sticky header is solid (`#EAF6FC`) since the page scrolls under it. ## Gotchas

- Sleeper roster `fpts` etc. are split into integer + `_decimal`/100.
- Sleeper team defenses use the team abbreviation as player ID (`"DET"`). Ranking sites spell some teams differently; `TEAM_FIX` in `sources.js` normalises (JAC→JAX, WSH→WAS…).
- Players the sources haven't listed yet (fresh signings) project 0. Patch them in `OVERRIDES` in `lib/overrides.js` (`{pos, wk}`); `app.js` applies it before `computeLeague`, only while the consensus has no `wk` for that player, and the footer lists active patches. Remove entries once the sources catch up.
- Name mismatches go in `NICKNAMES` (e.g. Bam Knight → Zonovan Knight, Cameron Skattebo → Cam Skattebo). Check `/api/ros` → `sources.*.matched` after changes; ~190 of 194 rostered players should have values.
- Scrapers may be blocked from Vercel IPs (browser-like User-Agent is set). A failed source degrades gracefully; don't make the whole endpoint fail on one source.
- Sleeper asks for `/players/nfl` at most once a day; only `api/ros.js` calls it, and the edge cache enforces that. Never call it from the browser.
- Sleeper is called only by `api/league.js` and `api/ros.js`, on the clock: once per morning, plus the Sunday late pull and the Monday final pull for the league. Keep pulls to that schedule: none on deploys, for testing, or from new features. Keep reads going through `once()` with a clock key, never add browser calls to Sleeper, and ask the owner before adding any new Sleeper read or pull time. Testing uses the demo snapshot and `?at=` (which fakes the page clock only; data keys follow the real clock).
- Ranking data belongs to FantasyPros, DraftSharks and LeagueLogs; this is a personal, non-commercial league site. Keep the attribution in the footer.
- There is no footer sponsor block on this branch (it was removed with the original league's details).
- Anything tappable to expand uses the shared `XP` circle in `app.js` (`.xp` in CSS), which flips when its parent is open.
